# Bassline

A system for partial information programming. Programs contribute values to local working memory and build their own understanding from what they hold.

CLAUDE.md is a symlink to this file. On layout and builds, the code wins when this file disagrees; fix this file. On the model, the code lags: stale code is being removed as the model settles, and `.claude/skills/bassline` describes the model as it stands.

## Read this first

- [data-model.org](data-model.org) defines values, the canonical encoding (CE), and the textual syntax. Read it before touching anything under `core`.
- Read the [Bassline skill](.claude/skills/bassline/SKILL.md) before designing with tracks, monitors, and dialects. The `bassline-zoo` skill covers other languages and format doors. The `bassline-reviewer` agent reviews designs against the model.
- [README.md](README.md) introduces Bassline and the layout in a page.

## The model in one paragraph

Programs exchange values whose identity is their canonical encoding. A track is the local interface for contribution, retention, and inquiry. An admitted `add` gives a value a place in working memory. Readers can inspect the entries still held, use a query offered by the track, or attach a monitor to follow changes. A monitor can materialize a dialect reading or offer an occurrence to another track. A reader that learns a dialect today can apply it to a value kept yesterday.

## Layout

Code added here is one of a few things: a kind of track, a monitor, a kind of live object, or a reading that turns what was said into live objects. Each of those serves a dialect, so the repository is organized by dialect, not by kind of code and not by language.

- `data-model.org` and `corpus/` stay at the root. Everything links to them.
- `core/LANG` is what every program needs to take part at all, in one language: values, CE, the textual syntax, tracks and monitors, and value literals in the host. Nothing about a particular conversation goes here.
- `dialects/NAME` is everything that speaks one dialect, in whatever languages it is spoken. Its README says what is spoken and what it contributes on each axis.
- `tools/` is the `bl` command line and the editor support.
- `legacy/` is what the track model replaces, kept building while something still runs on it.

The root `pnpm-workspace.yaml` holds `core/ts`, `legacy/js` and `tools/vscode`, since the editor support still depends on `@bassline/core`. The root `pyproject.toml` makes `core/py` and `dialects/jam/plugin` one uv workspace, with one `uv.lock` and one `.venv` at the root. `.agents/plugins/marketplace.json` is Codex's local marketplace for the jam plugin. `reorg.bl`, when present, is the working log of the reorganization and isn't committed.

### core/nim

The Nim implementation, the package `bassline`, and the one the model is worked out in. It needs Nim 2.4 (its nodes are a sum type). Import it whole, `import bassline`, which exports the four modules under `src/bassline/`. Its [README](core/nim/README.md) walks through tracks with an example.

- `micro.nim` is values and nodes, top to bottom: limits (`MaxDepth`, `MaxValueBytes`, both `{.intdefine.}`), `BasslineError` and `refuseWith` (a module's own `refuse` and `guard`), kinds and the header table, the atom laws (canonical integers, UTF-8 checked a word at a time), `BNum` (an `int` when it fits, a `BigInt` from `bigints` when it doesn't, with arithmetic that widens rather than overflows), `SortedTable` and `SortedSet` (sorted sequences found by bisecting), then `Value` and `Node`. A `Value` is an object variant with its mark: `vnum`, `vstr` for text, symbols and bytes, `vseq` for lists and records, `vdict`, `vset`. A `Node` is `Plain(value)` or `Bound(live)`, and a frame's members are nodes, so a live host object (`Live`, a ref object) can stand anywhere a value can. `cmp` is CE order, and a live node sorts after every plain one and equals only itself. `null`, `atom` and `frame` build values and check their laws. `reify` replaces every live node it reaches through plain ones with what its `reified` method says it stands for, and leaves the live nodes inside what those stand for unless asked to go deep. `reified` goes all the way. The reader (`initReader`, `readCE`, `readEach`, `readOne`, `readAll`, `starved`) reads CE in pieces from any `openArray[char]`, and `write` writes into any `Enc`, a string among them, refusing a live node. The sugar at the end (`Null`, `Num`, `Text`, `Sym`, `Bytes`, `List`, `Rec`, `Dict`, `Set`, which give nodes, `!` and `~` for the mark, indexing, `contains`, `incl`, `isKind` over a kind or a set of kinds with `marked`, `unmarked` or `anyMark`, `rewrite`) is convenience over what comes before it, and nothing before it leans on it.
- `text.nim` is the textual syntax over petit-parser: `Value.parse` (exactly one value), `Value.parseMany` (a document), `$` and `toBlText`. `basslineValue(extensions, reserved)` is the grammar a dialect extends with words of its own, tried before a symbol. A set or dict that repeats a member or key is refused.
- `micro_macros.nim` is values written in Nim, read from the textual syntax at compile time. `bl"…"` builds the node it spells: `$name` splices a node bound in Nim, `$name!` marks it, `@names` spreads a sequence of nodes into the list, record or set it stands in, a name is spelled as in bassline (`$foo-bar` is `fooBar`, `$p.x` a field), and a doubled sigil (`$$x`) spells the symbol with one. `blet` names values: a set of symbols names each symbol, and a dict names each value by its key. `matchValue v:` tries `of "PATTERN":` branches in turn, among `elif` and `else`, and runs the first that fits with its holes bound by `let`. A list or record fits one of its kind, mark and length, or at least that length when it ends in a rest `&name`, bound as the `seq[Node]` after. A dict or set fits one of its mark holding what it names, an atom an equal one, `$name!` only a marked value, `$_` and `&_` anything, and a live node only a hole. Holes go anywhere but a dict's keys or a set, each once. `{any-mark}` after a pattern fits whatever the value's own mark. A branch naming a Nim value fits a subject equal to it. The subject may be a `Node` or a `Value`. Sigils are read once into live `Sigil` nodes, which code generation and pattern fitting then dispatch on.
- `tracks.nim` is tracks and monitors. `add` is the only way to make a slot: an `add` during another write is `Staged` and asked of `keeps` when its turn comes, and otherwise it is `Kept` or `Ignored` at once. Slots are `Present(n)` or `Absent`, never renumbered, and the track only grows. `revise` (and `reviseIt`) is the holder's own step: a `Draft` over the committed slots replaces (`it[i] = n`) or vacates (`it.delete(i)`) and never moves or appends, and it isn't asked of `keeps`, so a slot can come to hold a node no `add` admitted. A reader that caches by position, or relies on what `keeps` admitted, reads again on `revised`. A revision during another write raises. A draft that raises discards its edits and the additions staged during it, and a hook that raises after commit leaves the change in place. A track hears its own writes through `keeps`, `added` and `revised` before any monitor does. A monitor attaches with `m.track = t` or `t.up(m)`, leaves with `t.down(m)`, and hears `joined`, `added(i, entry)`, `revised(swaps)` (each changed slot with what it held before) and `left`. A monitor attached by another during delivery waits for the next change. A hook that raises doesn't stop the turn, and the writer receives the first error once every monitor and staged addition has had its turn.
- `tests/`: `tcorpus` (every case head, reading `corpus.blb`), `t_micro_macros`, `t_micro_values` (live nodes, reify, writing), `ttracks`, and `t_micro_live` (bindings as live nodes). `bench/codec.nim` checks round trips, then times decode, encode and print over generated jam-shaped values or a `.blb` named on its command line.

### core/ts, core/py, core/swift

They agree with `core/nim` on values, CE and the textual syntax, and run the shared corpus, but they predate tracks and monitors and are built around the searches, streams and shapes the track model replaces. Each needs bringing up to the model `core/nim` holds.

- `core/ts` (`@bassline/blts`) is TypeScript: strict `tsc`, source Node runs directly (`.ts` imports, erasable syntax only), built to `dist/`, tested by vitest. It ports values (`values.ts` over `btree.ts`, through `Factory` interfaces), CE (`codec/`, a resumable decoder), text (`text/read.ts`, `text/print.ts` with `print` and `pretty`), the JSON carrier (`json/`), the `bl` template tag and `toValue` (`ops.ts`), streams, shapes (`shape.ts`), objects (`object.ts`), searches (`search.ts`, whose names may resolve to live `Search`es), finds (`query.ts`, the same query language as legacy `find.nim`), scopes (`scope.ts`), files by digest (`fs.ts`) and layers (`layers.ts`, runtime objects beside values). `src/micro.ts`, kept out of the index as `@bassline/blts/micro`, is the start of a port of `micro.nim`: kinds and headers, CE order, `Live` with `reified`, nodes, reify, the reader and writer, constructors and immutable editors. It doesn't have text, `BNum` arithmetic, the macros or tracks yet, and it still has the flat positions `core/nim` dropped. The web notebook links this package.
- `core/py` (import `bassline`, project `bassline`) is Python: values that cache their CE, the codec, text, readings between Python objects and values, the carrier, walk, fold and `prefixes`, searches and streams (`search.py`, with `Heard`, which keeps each value once in arrival order), the edge over file descriptors and pipes (`edge.py`), and the format doors behind `bl-magic` (CE, text, JSON, the carrier, CSV, TSV, TOML, XML, YAML) with their levers as `bl-search-NAME`. It has no tracks or live nodes.
- `core/swift` (package `Bassline`) is Swift: values with B-tree collections, CE (`StreamDecoder`, and an `AsyncSequence` over bytes), text (single-line printing), host bridging (`ValueConvertible`), shapes, and searches as `Search` and `Answers`, with shape matching as a search in `ShapeSearch.swift`. It has no tracks, live nodes, JSON or transport.

### dialects

`dialects/crypto` is digests and signatures over values, and how identity is spoken: a signature holds when it checks against the CE of the value it signs, under the scheme it names. Its [README](dialects/crypto/README.md) says what is spoken. `dialects/crypto/nim` is the package `bassline_crypto` over `core/nim` (`import bassline, bassline_crypto`), with monocypher vendored and nimcrypto from `deps/`. Its `nim.cfg` names `core/nim`'s source and dependencies. It digests with `blake2b`, `sha256` and `keccak256`, and signs with `ed25519` (standard, checked by Node's own Ed25519 byte for byte) and `eddsa-blake2b` (what blnim and the jam's keys use). `toNode` writes a digest, key `(key SCHEME KEY)`, signature, signed value or keypair, and `toDigest`, `toPublicKey`, `toSignature`, `toSigned` and `toKeypair` read one. `newKeypair` draws a seed from `std/sysrand`. It refuses a key of small order, which monocypher's check accepts with a trivial signature over anything.

`dialects/jam/plugin` puts Claude Code and Codex sessions on a jam through `bl-jam mcp`. `bin/jam-mcp` runs the `bl-jam` built in `tools/cli`, signing with `~/.bl/keys/$JAM_NAME.blb` when that key is there, and `bin/claude-jam NAME` makes the key the first time a name comes. `bin/codex-jam` is the Codex launcher, which installs `core/py` into a private runtime. Its README says how to run a jam across machines on a local network.

Most dialects spoken in this repository still live with the code that first spoke them, and most are described only in module headers. Each is to move into `dialects/NAME` with a README. Paths under `lib/`, `queries/`, `lang/` and so on are in `legacy/blnim/src/bl`.

- **jam**: `(Q A)` puts, `(Q)` asks, and the jam tells `(Q R A)`, R its own order, and `(Q nil A)` for an answer it passes through unkept, told only to the lines asking Q then. It answers `(jam)` with `!{(identity NAME) (identity BYTES) (at MS)}`, answers `(passes)` with `(passes nil SHAPE)` for each shape it passes through, and keeps `(here …)`, `(gone …)`, `(rooms ROOM)` and `(stamps NAME)`. What people share on it is a message, `(ROOM !{(by ID) (said V) (at MS) (re DIGEST) (for NAME)})`, with `(for NAME)` someone's own room and `(for all)` everyone. `lib/jam.nim` and `lib/server.nim`, `conv/jam.nim`, and in `tools/cli/src` `bl_jam`, `jam_client`, `jam_tui`, `jam_bridge`, `jam_scan`, `jam_kept`.
- **the jam's agent tools**: `heard` answers `(heard Q R READINGS A)`, READINGS `{digest jam by signer vouched re to-you}`, and `tell` answers `(put Q R)`, `(asked Q N)` or `(note …)`. `tools/cli/src/jam_mcp.nim`, read in Python by `dialects/jam/plugin/scripts/codex_bridge.py`, described for agents in `dialects/jam/plugin/skills/jam/SKILL.md`.
- **fs, files as values**: content asked by `(digest blake2b H)` and answered by bytes, `(chunks SIZE [D …])` and `(chunk BYTES)`, `(tree {NAME: ENTRY})` with `(file D SIZE MODE)`, `(dir D MODE)` and `(link TARGET)`, and names as signed `((alias NAME) D)` puts. Over a jam it is spoken by **the keeper**, `bl jam keep` (`tools/cli/src/jam_keep.nim`): it hears its rooms (`fs` by default) and its own, answers `(want D …)` with `(has D)` and then puts `(D V)`, and on `(keep D …)` fetches D and everything under it, saying `(want D)` for what it lacks and `(kept D)` once it holds it all. `lib/fs.nim`, `lib/fs.bl`, `lib/fsnames.nim`, `tools/cli/src/bl_fs.nim`, `core/ts/src/fs.ts`.
- **jam sharing**: a search space put on a jam, `(knowledge D)`, `(D SPACE)`, `(found QUERY {ANSWER})`, `(more (found QUERY))`, `(sharing DIGEST TEXT)`. `tools/cli/src/jam_share.nim`.
- **parties**: where programs on one machine meet. A connection is told `(name N S P)`, says `(sub T)`, `(unsub T)`, `(say T V)` and `(own {T …})`, and is told `(said N T V S)`, with `(alive S)` and `(dead S)` under `status`. `parties/`, `tools/cli/src/bl_party.nim`, and the experiments in `legacy/blnim/examples/parties`, among them an earlier party keeper (`explore/apps/keeper.nim`).
- **crypto, digests and signatures**: `(digest ALGO HASH)`, `(signed V SIG)` and `(signature SCHEME SIG KEY)`, now in `dialects/crypto`. The earlier implementation is `lib/crypto/`, with `tools/cli/src/bl_clave.nim` and `bl_hash.nim`.
- **tea-time**: one order kept by one key, `(signed (tea-msg N AT PREV V) SIG)` and `(tea-sync KEY LO HI)`, and a jam's stamps `(tea-msg R T PREV (Q D))` under `(stamps NAME)`. `lib/teatime.nim`.
- **evidence**, **hidden** and **claims**: roots, proofs, checkpoints, receipts, equivocations, openings, a value by its tree's digest with any part shown, and claims a reader checks against its premises. `lib/evidence.nim`, `lib/hidden.nim`, `lib/claims.nim`, described in the legacy section below.
- **search spaces, finds, sends and bvars** written down as objects: `!{!(kind search-space) …}` and its composites, `!(kind find)`, `!{!(kind send) !(to ID)}`, `!{!(kind bvar) …}`. `queries/`, `lib/bvarfile.nim`, `core/ts/src/search.ts`, `query.ts` and `object.ts`, `tools/cli/src/bl_search.nim`. The track model replaces these as the building block, and the skill's `references/search.md` has the worked examples.
- **shapes**: `(shape EXAMPLE {HOLE …} WILD)`. `queries/rewrite.nim`, `core/ts/src/shape.ts`, `core/swift` `Shape.swift` and `ShapeSearch.swift`.
- **doing marked values**: calls `!(HEAD …)`, blocks, `(fn PARAMS BODY CAPTURED)`, `(rule (shape …) BODY)`, the base vocabulary, and `!(rpn […])` as a dialect inside a doer. `lang/`, `legacy/blnim/lang.org`, `tools/cli/src/bl_eval.nim`.
- **struct descriptions**: `(struct NAME {PRAGMAS} (FIELD TYPE) …)`, the types of fs, blarc, evidence, claims and crypto. `mold/`.
- **conversations**: a shell's commands `!(set)`, `!(get)`, `!(say)`, `!(serve-tcp)`, `!(connect-tcp)` and the rest, with `(failed CMD WHY)` and `(unknown CMD)`, and the examples in `legacy/blnim/examples/conv` (an auction, blitcoin). `conv/`. No tests.
- **grammar blocks**: `lang NAME [[ … ]]` with `sexp`, `json` and `uri`. `grammar/dialects.nim`, `grammar/uri.nim`.
- **the JSON carrier**: `{"kind", "mark"?, "value"}`. `lib/json.nim`, `legacy/js/src/json.js`, `core/ts/src/json/`, `core/py` `carrier.py`, and `corpus/corpus.json`.
- **door vocabulary**: what `core/py`'s doors read foreign documents into, `(dec M E)`, `(number "S")`, `(date …)`, `(time …)`, `(datetime … (offset M))`, `(object [K V] …)`, XML elements as `(TAG {ATTRS} CHILD …)`, and the levers over them. `core/py/src/bassline/doors`, `levers.py`.
- **tracks written down**: `!(track [(present N) … Absent …] [MONITOR …])`. `core/nim/src/bassline/tracks.nim`.
- **smaller ones**: the person's own answers, `(Q A)` in `~/.bl/config.bl` with `((place NAME) PLACE)` and `(defaults TOOL …)` (`tools/cli/src/bl_config.nim`, `bl_name.nim`), the groceries app (`legacy/blnim/examples/lang/groceries.bl`), blarc's archive (`legacy/blnim/examples/archive.bl`), and the corpus's own cases.

### tools

`tools/cli` is the Nim `bl` toolkit over `legacy/blnim`: `cat`, `read`, `send`, `serve`, `reach`, `ws`, `hash`, `search` and `eval`, each a small tool over bare concatenations of CE on stdin and stdout. Signing is apart in `bl-clave`, files as values in `bl-fs`. The jam is apart in `bl-jam`: `bl jam serve` serves a jam kept by name in `~/.bl/jams/NAME.blb`, listening on every interface unless given a place (`--as NAME`, `--new` to begin one, `--clave` for signed values only, `--key` for a tea-time order), `bl jam list` says what each kept jam holds, `bl jam running` lists every jam served and bridge running on this machine (each says so in `~/.bl/running/PID.blb`, held locked while it runs) and `bl jam stop` stops them, `bl jam scan` finds what answers on this machine's networks, `bl jam` is a terminal on one, `bl jam mcp` puts an agent on one, `bl jam share` shares a search space on one, `bl jam keep` keeps files for one, and `bl jam bridge` puts on each of two jams what the other tells it, as it was put, so jams on several machines carry one conversation. A client (`jam_client.nim`) that hears it is gone after its own `here` says `here` again, since a jam says that when the line that brought the `here` goes, a bridge's among them. `bl config` keeps the person's own answers, `(Q A)` records in `~/.bl/config.bl`, where a tool looks for what its command line and environment don't say (`at`, `as`, `send`, `serve`, `listen`, and `(defaults TOOL…)`, the options a tool is given ahead of its command line, which `--no-defaults` leaves out), and `bl name` keeps names for places there as `((place NAME) PLACE)`, a name then being the place it names wherever a place is taken. Tools from any implementation join by being `bl-NAME` on PATH. Its `nim.cfg` is checked in and names `../../legacy/blnim/src` and the dependencies in `legacy/blnim/deps`. `tests/t*.nim` drive the built tools, split by what they drive (`tbasics`, `tplaces`, `tclave`, `tjam`, `tplugin`, `tws`, `tfs`, `tkeep`, `tfsbridge`), sharing `tests/cli.nim`, which gives the tests a home of their own so nothing in the person's `~/.bl` is touched. `nim test` runs them all and `nim test jam` one. They aren't ready to run on this branch yet.

`tools/vscode` is editor support for `.bl`. Its reader is blnim's grammar (`grammar/js.nim`) built with `nim js` by `pnpm reader`.

### corpus

`corpus/corpus.bl` at the repo root is the shared corpus every implementation runs: values with their expected CE bytes, bytes a decoder must reject with a reason from a closed list, prefixes a decoder must wait on, and the reader's own cases, 150 in all under seven heads (`ce`, `reject`, `starved`, `reads`, `refuses`, `incomplete`, `document`). Every case is input given in total; input that runs out inside a value is kept apart from rule-breaking because a reader still being given more waits there instead. Its expected bytes come from the spec, never from an encoder. `corpus.json` (the same records in the JSON dialect) and `corpus.blb` (the same records as a bare concatenation of CE) are derived from it by running `legacy/blnim/tests/corpus.nim` as a program; regenerate whenever the `.bl` changes. Imported, the same module is the loader blnim's tests share: `cases`, and `filter` by case head. Every implementation runs every head. `core/nim` reads `corpus.blb` alone, and the others also check that `corpus.bl` and `corpus.json` read back as the same cases.

### legacy/blnim

The earlier Nim implementation (Nim 2.2, ORC), larger than `core/nim` and built around searches, sends and bvars, which tracks replace as the building block. The jam and the `bl` tools run on it today. Its jam, fs, clave, tea-time, evidence, hidden, claims, lang and conversations are dialects waiting to move into `dialects/`.

`legacy/blnim/src/bl/core`

- `codec/shared.nim` walks CE bytes as nil, atom, open, close events. Starvation raises, so a decoder can resume when more bytes arrive. `refuseWith Err` gives a module a `refuse`/`guard` pair that raises `Err`, bound where they are written so a generic refuses with its own module's error. Every refusal is a `BasslineError` (itself a `ValueError`): `CodecError`, `ReadError`, `MoldError`, `JsonRefusal`, and the plain `BasslineError` the other modules raise. `MaxDepth` caps frame nesting; `MaxValueBytes` (both `{.intdefine.}`) is the default cap on bytes buffered toward one value, overridable per decoder via `newDecoder(maxValueBytes = …)`.
- `codec/decode.nim` builds `ValueView` trees that borrow the buffer. Validation is deferred and memoized per node. `compact` drops already-decoded bytes so a long run of input stays bounded.
- `codec/encode.nim` is the writer.
- `builders.nim` is `Value`, the in-memory reading: an object variant with `cmp` in CE order. A number is a `Num`: an int64 when the spelling fits, otherwise the spelling itself, so every integer is held and `toInt` is the reading that refuses. `ce(v)` is a value's CE bytes.
- `btree.nim` backs dicts and sets so canonical order holds by construction. `itemsFrom`/`pairsFrom` take a bound as a key or as a monotone predicate (a bound that needn't be a member, such as "every record headed by q"), and bisect to it.
- `reader.nim` reads and pretty-prints the textual syntax. `Reader` (`add`, `items`, `finish`) reads text in pieces and yields each value once nothing still to come can change it.
- `buffer.nim` is the growable byte `Buffer` the codec shares.
- `value_macros.nim` is values written in Nim, read from the textual syntax at compile time. `bl"…"` (`blfmt`) builds a value as it would be built by hand, `$name` splicing the Nim binding `name` through `toValue` (`$foo-bar` is `fooBar`), `$name!` marking what goes in, `@name` spreading a seq, or a list's or record's members, into the frame it stands in, and a sigil doubled (`$$name`, `@@name`) the symbol with one. `bl("…", mark)` says the outermost value's mark at runtime, the text then saying none. `blet` binds names to symbols or values. `matchValue v:` tries `of "PATTERN":` branches in turn, among `elif` and `else`, and runs the first that fits with its holes bound by `let`: a list or record fits one of its kind, mark and length, or at least that length when it ends in a rest `&name`, bound as the `seq[Value]` of the members after, a dict or set one of its mark holding what it names, an atom an equal one, `$name!` only a marked value, `$_` and `&_` anything. Holes go anywhere but in a dict's keys or a set, each once. A pattern may be followed by its options, a set: `{any-mark}` lets the value fit whatever its own mark. It is a statement, or an expression when it ends in an `else`, and it reads a list's or record's members as code written by hand does.

`legacy/blnim/src/bl/store`

- `store.nim` is an append-only, copy-on-write B+tree holding a monotone set of CE byte strings. Key-only: an element's bytes are its key, its value, and its identity. The store never interprets elements. Because CE spells the record head first, a prefix scan is a query for every value under a head.
- `backends/` is the page arena interface with an mmap instance and an in-memory instance that produce byte-identical pages.
- `values.nim` is the value face over the store (`incl`, `contains`, `under`, `low`, `high`), aggregated by `bl/store.nim`. `under` scans by `frameKey`, the byte prefix that selects exactly the values a value `prefixes`.

`legacy/blnim/src/bl/mold` (`bl/mold.nim` aggregates)

- `parseMold.nim` reads a description into a tree, the same at compile time and at runtime: `(struct NAME PRAGMAS? (FIELD PRAGMAS? TYPE) …)`, or a set of structs declared together. PRAGMAS is a set of flags and `(KEY VALUE …)` records: a struct takes `exact`, `(rep dict|record)` and `(nim NAME)`; a field `optional` and `(nim NAME)`; `bytes` takes `(len N)` and `symbol` `(one-of S …)`. A TYPE is a kind (marked by `!`), `value`, `any`, a struct by name, `(list|set|record T)`, `(dict K V)`, or the shorthand `[T]`, `{T}`, `{K: V}`. Nim names come from bassline names (`new-chunks` is `newChunks`) unless `(nim …)`. Each struct carries its `Shape`; a `Context` holds the structs by name.
- `moldMacro.nim`: `moldable TEXT` (a literal, a const or a `staticRead`) generates, for each struct, a public `Moldable` ref type and all of its reading and writing: `moldFields`/`loadFields` by name, `moldDict`/`loadDict` as `(NAME {FIELD: VALUE …})`, `moldRec`/`loadRec` as `(NAME VALUE …)` in field order (nil where an optional field has nothing), and `mold`/`load` in the form `rep` names; and `shape`, the struct's head, mark, form, field names and description. The description's mark is the value's. Reads leave undescribed fields behind unless `exact`. Probes (`T.probe(v)`, `probeDict`, `probeRec`, `probeFields`, and `T.fits(v)` for a yes or no) check what the load would, refusing with the same words, and build nothing. Two hooks are written by hand, often on a subclass holding host-only state: `beforeMold` runs before every write, `afterLoad` once, when a value is first read into a new object (`T.load` and the like, conversion, Poly), and may refuse; a probe builds no object, so what a hook refuses only a load hears.
- `mold.nim`: the `Moldable` base, `Shape` (whose `fieldsOf` and `valueOf` read and write either form by name), the generic loaders by type (`T.load`, `T.loadFields`), `convert` (by name, CLOS-style), and base versions of every form, working from `shape`, for a Moldable written by hand.
- `poly.nim`: `Poly`, fields by name read through whichever Moldable face is asked for; the live face's fields are written back wholly, so a field it leaves out is left out.

`legacy/blnim/examples/archive.nim` is `blarc`, a content-addressed directory archiver whose values are all described in `archive.bl`.

`legacy/blnim/src/bl/queries` (`bl/queries.nim` aggregates `queries.nim`, `bvar.nim`, `rewrite.nim` and `find.nim`, and through them `stream`, `search` and `send`)

- `rewrite.nim` (exports `queries`, `stream`): shapes, an example value with an explicit set of holes, `(shape EXAMPLE {HOLE …} WILD)`. Filling one is a little unification search: `fillings(shape, v, given)` answers every binding of the holes under which v fits the example and that is compatible with the bindings `given`, one per pull, nothing worked out ahead. A hole in a dict key or set member is tried against each actual key or member, and a hole met again fits only what it is bound to. `search(shape)` (in `search.nim`) is the same as a `Search`; `inject` fills the holes bound and leaves the rest. Each part of the example is a search from bindings to their extensions, and a frame's are composed one after another: first what the bindings already decide, then what has one place to fit, then the part narrowest by its known leading members, each list or record member looked for only in its `ledBy` run. `fitting(shape, forms)` lets a dialect built on shapes read some marked parts its own way.
- `find.nim` (exports `rewrite`): the query language. A find is one more kind of search space, `!{!(kind search-space) !(kind find) (of SUBJECT) … (hole H) … (asked H) … (where CLAUSE) … (gives W) …}`: each clause a shape's example fitted against a subject's records, the bindings fed from clause to clause (those that only check first, then those whose question is settled, which bisect, then scans), each binding answered once as each gives with its holes filled. Clauses may hold the forms `!(within P)`, `!(any P …)`, `!(all P …)`, `!(as H P)` (binding H whatever its mark) and `!(quote V)`; `!(kind distinct)`, `!(kind count)` (running counts) and `!(kind why)` add to it. A subject is a held space, a composite, another find, an object (its own records), or names of one; a ranked record (Q R A) fits a clause (Q A). `Find.fromValue` reads one, `find` writes one, and `rows` (here over `Subject`s, in `search.nim` over a find value with `resolve`) answers `Row`s with which part answered each clause, and with which record. `search.nim` reads a find back like any space (`findSearch`, `fromValue`), its `(asked H)` holes bound to what it is asked, so finds compose with spaces through cat, alt, feed and merge.
- `stream.nim`: the stream (`Stream[A] = () -> Option[A]`), `empty` (allocates nothing), `just`, `lazy`, `next` (the next pull, an `Option`), `k` (the constant proc), the combinators (`map`, `filter`, `filterMap`, `tap`, `flatMap`/`catFrom`, `alt`, `altFrom` over a stream of streams, `cat`, `merge` by an order, `first`, `take`, and the sugar `|`, `&`), `exists` and `every`, and the `it` forms (`maps`, `filters`, `filterMaps`, `flatMaps`, `taps`) for the combinators whose result type comes from the lambda. It exports `std/sugar`, so `x => body` lambdas, `(A) -> B` proc types and `collect` are had everywhere streams are; a stream becomes a seq with `toSeq`. A generic alias of a proc type (`Pred[A]`) stops `=>` inferring its parameter, so signatures spell `(A) -> bool` out, and a lambda in a generic proc types its parameter.
- `search.nim` (exports `stream`): `Search[Q, A]`, a ref object that closes over whatever it answers from (`newSearch`, `ask`, `s[q]` for every answer as a stream, `s ? q` for the first, and `id`, from an id proc or a value, so naming a search doesn't write it down). Its `fanout` is `many` (set semantics) or `one` (dict semantics: at most one answer a query); a dict space reads as `one`, and `memo` keeps a dict for `one`, a set for `many`.
- `queries.nim`: streams over values to compose from, and what objects answer. A frame's `parts`, a depth-first `walk` through everything inside a value, a set's `members`, a dict's `entries`, a set's members `between` bounds (`ledBy`: its lists or records that begin with given members; `headed`: its records under a head), found by bisecting, each pull resuming past the last value given; `unique`. Predicates are plain functions taking the value first (`isKind`, `hasWidth`, `isObject`, `always`; `prefixes`, whether one value is what the other's CE yields when stopped early; `similar`, a match by kind and mark all the way down, a frame in the exemplar maybe shorter), used through `x => …` lambdas or the `it` forms; `sameFamily` is whether two values share kind and mark, `map` makes a frame over part by part, and `toAnswer` reads a record as an `Answer`. An object is a marked set of records shaped as answers: unmarked `(Q A)` is answered, marked `!(Q A)` an order, such as its kinds `!(kind K)` or a send's `!(to ID)`; `answers`, `orders`, `kinds`, `targets` are streams over its run for a head, and `answer` takes the first. A thing's names are its answers to `identity` (`identities`, `knownAs`, `sharesIdentity`, `alsoKnownAs`, `identity`, `identityOf`, `randomId`); `describe` writes an object; the shared kinds and questions live here.
- `send.nim`: `Send[Q, A]`, an object like `Search`: a send proc (`send(q, a)`, runtime things as readily as values, answering whether it was taken) and an optional denotation; a send has no name of its own, it is told apart by what it sends to. Written down a send is opaque, `!{!(kind send) !(to ID) …}` (`sendTo`): only that it is a send and what it sends to, by identity. `tee` tells several, and writes down as the union of their targets. Reading a send back is a search from identities to sends: what an identity reaches depends on where it is read.
- `bvar.nim` (exports `search`, `send`): `BVar[Q, A]`, a program-level place: a `Send` and a `Search` over it, written down when its halves can be as `!{!(kind bvar) (identity ID) (send …) (search …)}` (a missing half not answered), to put things (the write half, `send(q, a)`, runtime things as readily as values) and search what has been put (the read half, a `Search`; `read(v)` asks nil). Either half may be nil; `access` (`none`, `r`, `w`, `rw`) is computed from which it has, and `readOnly`/`writeOnly` drop one. `spaceVar` holds a search set in memory (a dict for `one`: the first answer stands), empty or a copy of a denoted space (a dict only when it holds one dict, otherwise every record it holds); its send is `!{!(kind send) !(to ID)}`, and a bvar pairing a space with a send to it reads back (`BVar.fromValue`) as a live space var. `persist` hands the space, written down, to a keeper on every send it takes. `memo(s, into)` answers from what the bvar kept, then what `s` finds that's new, keeping it; `memo(s, id)` keeps it in memory. `v[q]` and `v ? q` read like a search's. `union` makes many places one: sends tell all, reads alternate (a primary resolver is a union of many). Streams over a space hold a value, not a place in the set, so the space may grow while they are open. A search may be denotable: its space written down as an object, `!{!(kind search-space) (identity ID) (holds {(Q A) …})}` (a dict in `holds` for one answer a query, `!(kind ranked)` for `(Q R A)` records), and `Search[Q, A].fromValue` interprets one back into a search whose answers are rebuilt by A's reading (`skipRefused` passes over refusals). `toValue` writes one down; `searchOver` searches a set or dict held now (written down as a copy). Searches compose into searches (`cat`, a scope then the scope around it; `alt`; `feed`; `merge` by rank; `more`, one search asked again of its answers, nearest first, each once, with `!(kind via)` answering `(via [Q … PREVIOUS] A)`), written down as `!{!(kind search-space) !(kind cat) (identity ID) (parts [PART …])}` and so on, a part carried whole or named by ID (`byId`) and resolved, when asked, through a search of known spaces (`fromValue(…, resolve = …)`). An ID may be an identity of several names; a name resolves through each of them, and a name met again on its own way round is passed over. Several `holds` or `parts` answers are joined as the kind joins its parts, merged by rank when ranked.

`legacy/blnim/src/bl/lang` (`bl/lang.nim` aggregates): doing marked values. [legacy/blnim/lang.org](legacy/blnim/lang.org) is the convention, ideas only.

- `kernel.nim`: `Cx`, where a value is done (variables, doers, the cx around it; `within`, sealed for a function's body), `Doer` (`fits`, `answers`, `describe`), and `eval`, answering a stream. An unmarked value answers itself, whole. A marked record is a call: a marked head is done first, then its direct marked arguments, left to right, each later one once for each answer before it (crossed fairly, `fair`); everything else is handed over as said. The bound call goes to the doers found by its key (`keys`: a head, `(kind K)` for an object, a marked symbol after its variable, `(frame KIND)`), nearest first: the first that fits and answers gives its answers, nothing or a refusal passes it on, and nothing fitting is heard by `unheard`. A refusal is one branch's (`refused` hears it when passed over); a doer that acts says `acted` and owns the call. `run` does a block (an unmarked list) as arguments are done; `readings` is every doer's answers; `search` is doing as a `Search[Value, Value]`.
- `native.nim`: a marked moldable struct is a native's signature; its probe is `fits`, `T.load` binds, `method run(c: T, cx: Cx)` does it. Trailing optional positions may be left out.
- `base.nim`: `base()` holds a vocabulary (do, if, else, then, case, quote, all, first, count, take, in, let, fn and applying a function value, record, rules, arithmetic refusing past int64, lt/le/gt/ge/eq/ne answering their first argument or nothing, compare, range, len, has, lacks, get, fill, inject, describe, readings); `install(send)` gives `!(put Q A)`, answering `taken`, and `install(search)` `!(ask Q)`. A function is a value, `(fn PARAMS BODY CAPTURED)`; a rule is `(rule (shape EXAMPLE {HOLE …}) BODY)`, one doer each.
- `reps.nim`: `Reading[T]`, what a value reads as in the host, kept against its frame body, kind and mark (an atom's CE).
- `numeric.nim`: `cx.numeric`: dot, vsum, vadd, vsub, vmul, scale and matmul over whole lists, members read once (`Ints`, `Rows`).

`legacy/blnim/examples/lang`: `groceries.bl` and `ui.nim` (an app as values over a space, drawn in a terminal; a nearer rule changes it while it runs), `numeric.nim` (where the time goes; build with -d:release), `rpn.nim` (a dialect as one doer).

`legacy/blnim/src/bl/lib`

- `json.nim`: the kind-tagged JSON carrier (`toJson` / `fromJson`).
- `bvarfile.nim`: `fileVar`, a space var kept in a file holding one value, its space written down, rewritten (fresh file, then rename) on every send it takes; opened again it holds what it held. `valueIn` and `writeValue` are the plain file halves. `logVar` keeps a space var as a log instead: each record it takes is appended (`appendValue`), so the file is a bare concatenation of records, and opened again it holds them all (`valuesIn`, which cuts a record torn by a crash).
- `blah.nim`: random values for tests (`randValue`, `randPrefix`).
- `server.nim`: the edge for TCP sockets (unix sockets were dropped 2026-10-02 as not worth the macOS trouble). A connection is a bare concatenation of CE values. `newListener` hands every value that arrives, or its raw CE for a relay, to a local send; an optional observer hears open, close, truncated, malformed and failed, with the address, and nothing about the connection reaches program logic. `connect` dials, `pump` reads a dialed connection, `sender(conn)` is the outward send. `newListener(port, offer)` instead offers each connection to the program as the send that tells it, and the program answers a `Line`: where what arrives goes, and, once nothing more arrives, whether to keep telling it (until a tell is refused). Every connection, accepted or dialled, is probed once it has gone quiet for 30 seconds and given up after three unanswered probes, so an end that went away without closing ends it within about a minute.
- `jam.nim`: a place to put answers and ask questions, shared at the edge. The protocol is the arity convention: `(Q A)` puts, `(Q)` asks, and a `Jam` tells each line that asks the record `(Q R A)` for every answer, what it has and then as they come, R its own order heard. It reads no meanings; signed values (`crypto/clave.nim`) are taken as what they sign and kept signed; it answers `(jam)` with which jam it is, `!{(identity NAME) (identity ID) (at MS)}`, put once when its log begins and not put to by lines, so a client dialling its place again hangs up on another jam served there since; it puts `(gone …)` for whoever a line said was here, and hasn't said since is gone, once the line stops speaking or can't be reached, and, opened on a log, for everyone the log says is here. Given a key, its order is a tea-time order (`teatime.nim`): for every answer it keeps it puts under `(stamps NAME)` its reflector's next message, signed, `(tea-msg R T PREV (Q D))`, told at R, the rank it stamps and the message's ordinal, D the digest `re` names, T its clock, PREV the digest of the message before; a log whose ranks the key hasn't all stamped is refused. `stampOf`, `vouches`, `stamps` and `unchained` read them. The readers clients share: `heard` reads a told record, `keep` puts it in a reader's own ranked space and `heardIn` searches it, `who` reads presence and `wasHere` whether someone was here when the jam heard a rank, `Speaker` puts, asks and writes messages (objects answering `by`, `said`, `at`, `re`, `for`), and `isFor` says whether one names someone, or `all`, everyone who hears the room. Rooms are questions, `(for NAME)` is someone's own.
- `teatime.nim`: one order over values, kept by one key. A `Reflector` signs each value it is given with the next ordinal, its clock and the digest of the message before, `(signed (tea-msg N AT PREV V) SIG)`, PREV nil for the first; the key is the order's identity. A `History` holds what a reader has of one order, each message once by ordinal, checked as the key's (`add` answers `added`, `known` or `conflicting`; two words for one slot, or a message whose PREV names another word than the one held, are kept apart in `conflicts`, the word held first kept); its `gaps` are `(tea-sync KEY LO HI)` asks that any holder can answer by `replay`, `onward` the ask for everything after the highest held, and `initReflector(kp, history)` resumes an order from after it. Whoever acts on an order acts on what a history holds, in ordinal order, their own messages once reflected.
- `evidence.nim`: what an order entails, as values anyone can check, each a `moldable` struct: `(root N D)`, a tree over a run of values (leaf node the digest of `(leaf V)`, inner the digest of `(node L R)`, split at the greatest power of two below n); `(in ROOT I LEAF [SIB …])` and `(grows OLDER NEWER [SIB …])`, proofs of inclusion and growth that `holds` checks in log n digests; `(checkpoint OVER Q R ROOT)`, a reader's signed word on the answers it heard to Q from the order OVER (the jam's identity, `jamOf`) through rank R, put under `(checkpoints Q)` (`checkpoint`, `checkpointOf`); `(equivocation A B)`, two signed puts by one key for one `slot` `(slot OVER Q R)` that differ (`convicts`); and `(receipt (Q R A) STAMP)`, an answer as told with the jam's stamp for it (`vouchedBy`). A set's members in CE order are a tree too: `(opening ROOT RANGE I [LEAF …] [SIB …])` shows exactly the members in a range, `(from LO HI)` closed by CE order or `(under P)` (`opening`, `holds`, `members`, `absent`), and `(changed OPENING OPENING)` the whole change of a range between two roots (`scope`, `unchangedOutside`).
- `hidden.nim`: a value by a digest of its own tree, so any part can be shown to someone holding only the digest, or a signature over it. The tree mirrors the value: a part hidden whole is a leaf, the digest of `(leaf V)` or `(leaf V SALT)` (evidence's leaf node when unsalted); a frame hidden by its parts is the digest of `(KIND (root N D))`, marked as the frame is, with `(root N D)` the evidence tree over its parts' nodes in `parts` order, so there is one value under a digest by construction. `hide(v, apart, salted)`, both predicates over a part, keeps the `Tree`; `t.hidden` is `(hidden D)`, what a key signs; `t.shown(path)` is `(shown (hidden D) [(KIND N I [SIB …]) …] NODE)`, checked by `holds` in log N per frame passed, `part` the leaf's value, `frameOf` a frame node's kind, mark and width, `way` the steps read (`Step`, hand-read since its head is the frame's kind), `places` the way without its siblings, `(KIND N I)` each. A set hidden by its parts, its members whole and unsalted, is exactly the tree an `opening` checks against.
- `claims.nim`: evidence composed into one value a reader checks, `(claim FIND {EVIDENCE …})`, FIND naming no subjects and counting nothing. What evidence entails is `(Q A)` statements, only when the evidence's own check holds: `(in …)` `((in ROOT I) LEAF)`, `(grows …)` `((grew OLDER) NEWER)`, an opening `((opened ROOT RANGE) {M …})` and `((member ROOT RANGE) M)`, a changed `((scope OLDER NEWER RANGE) {added: … removed: …})` with `added`, `removed` and `unchanged-outside`, `(signed V SIG)` `((signed KEY) V)` and, for a put, `((put KEY Q) A)`, each with what V and A entail, a receipt `((stamped KEY) (Q R A))`, an equivocation `((convicted KEY) SLOT)`, a shown `((part (hidden D) [PLACE …]) V)` or `((frame …) NODE)`, raw CE bytes the codec reads as exactly one value `((reads B) V)`, claims within, and `((digest-of V) D)` answered on demand; a bare `(Q A)` handed in entails nothing. `entails` is this module's `Reading`; `entailments([…])` composes readings into one `Entails` search that nested evidence is asked of too. `convinced(claim, premises, entails)` asks the find of those statements and the reader's premises together, a `Subject` from an object or a held space (`premises`, `given`), and answers one `Conviction` per way the find came to an answer, `(convinced ANSWER {ENTAILED …} {GIVEN …})`, the records it rests on as held; `convincing` is the checker as a `Search` asked claims. A find's hole fits only its own mark, so a marked value such as a jam's identity is bound with `!(as H)`. An opening's exactness rests on the committer's sort, which a reader holds as its own premise.
- `crypto/`: `digest.nim`, digests over a value's CE bytes (blake2b-256 and sha256 via nimcrypto), `clave.nim`, keypairs, signatures, and signed values (EdDSA via vendored monocypher), and `crypto/types.nim` for the types the two share. Each type is a `moldable` struct (`Digest`, `Keypair`, `Signature`, `Signed`) with `{exact (rep record)}`: unmarked, its head, no item more (one would ride along unsigned), schemes and algorithms as `(symbol {(one-of …)})`, keys, hashes and signatures as `(bytes {(len N)})`, and any value, marked too, where a field holds one. A reading that doesn't fit refuses with `MoldError`, a `BasslineError`.

`legacy/blnim/src/bl/grammar`: the textual syntax and CE as grammars over `petit_parser` (github Bassline-Org/petit-parser-nim, which `blnim.nimble` requires by URL, so `atlas install` fetches it into `deps/`; for working on both, `atlas link` a checkout of it, and don't commit the path that writes into `nim.cfg`). Construction is split from validation. `text.nim` and `ce.nim` are the two syntaxes as grammars that build through a `Make[V]`, atoms from payloads and frames from members in order, checking only what the bytes alone decide (a known tag, a minimal length, a canonical integer spelling, a record head). `values.nim` is the rest: `makeValues()` builds `Value`s whose sets and dicts hold their members in written order in a sequence frame, and the value parsers (`ValueParser[R]` over `Members`, a frame read as one sequence, a dict's keys and values alternating; `listOf`, `recordOf`, `setOf`, `dictOf`, `symbol`, `number`, `ofKind`…) read any value the way text is read, with a path in the message. The pass is not a grammar but a walk that finishes a structural value where it stands, in the bodies the grammar built: `canonical(v)` is what CE needs (UTF-8, strictly ascending members and keys, nothing repeated, trees built from the order given) and `sorted(v)` what text needs (sorts, refuses repeats); each refuses with the path of the member that would not do. A parser over values pays one child input per frame it enters and nothing for positions, which are spelled out only for a message. `dialects.nim` is the extended syntax with `lang NAME [[ … ]]` blocks and the standard dialects (`sexp`, `json`, `uri`), `uri.nim` references as five slots, `js.nim` the editor's reader built with `nim js`. Tests are `tests/tgrammar_*.nim` and `tests/tvalues.nim`, run against `corpus/corpus.bl` and `.blb` with `reader.nim` and `Value.decode` as the oracles. The grammars sit beside `core/reader.nim` and `codec/decode.nim` until they read in pieces too; then they replace them.

`legacy/blnim/src/bl/lib` also holds `fs.nim`, files as values (content asked by its digest, trees of names, and a keep that holds values filed under their digests, described in `fs.bl`), and `fsnames.nim`, names for content as signed `((alias NAME) D)` puts on a jam, none of them the alias.

`legacy/blnim/src/bl/conv` (`bl/conv.nim` aggregates): conversations. A participant says a value into a conversation, and the conversation decides what is passed on: the message as said, something of its own, several, or nothing. `shell.nim` is a participant that does the marked commands it hears, so a program is put together from values. `stdio.nim` and `tcp.nim` are standard input and output and TCP connections as participants. `jam.nim` is the jam as a conversation. `host.nim` and `host.bl` put a program together this way, and `agent.nim` is a speaker with a body.

`legacy/blnim/src/bl/parties`: where programs on one machine meet. `parties.nim` is a daemon at the place of a value (`bassline`, on port 8455) where connections subscribe to topics and say values into them. `here.nim` is the party a program attends without asking. `place.nim` is a value's place, an IPv6 address in fd00::/8 whose other 120 bits come from the blake2b of its CE, so every machine reckons the same place for a value.

`legacy/blnim/src/bl/other_lang/tree.nim`: a value opened up to be worked on, a draft that may pass through states that are not values, and `finish`, which reads the value it stands for.

- Messages are gone: `bl/msg` (`Msg`, the router, `pool.nim` with `TaskPool` and `PubSub`) and `tests/tpool.nim` were deleted 2026-10-02 (7c70e1ba), after the listener stopped using them. Search replaced them for finding out what values entail, and a send is a proc over a value. `queries/rewrite.nim` (once `ops/rewrite.nim`) was rebuilt 2026-10-03 as a search for compatible bindings.
- `Decoder.compact` compacts while frames are open, so a long run of input stays bounded whatever the read boundaries.
- Removed 2026-10-02: `prop/` (lattices and cells), `lib/server/http.nim`, `store/par.nim` with `malebolgia`, and `tests/tops.nim`.
- The store is an exploration that will change; don't build on it now.
- Crypto's host types, and `blarc`'s, are `moldable` structs; the old hand-written readings and the description dialect before them are gone.
- Ruled and landed 2026-09-03: blnim's `Value` stays a value type. Atoms are copied like the strings and integers they hold. ### legacy/js

`legacy/js` (`@bassline/core`) mirrors the blnim `core` factoring:

- `src/codec/` is the CE byte grammar with no value knowledge — `header.js` (tags, mark bit, END, length tiers), `payload.js` (canonical-int / UTF-8 predicates, byte orderings), `buffer.js` (`ByteBuffer` growable store + `ByteCursor` + `Starved`), `events.js` (`walkEvents`, the nil/atom/open/close walk), `encode.js` (`Encoder`), `decode.js` (`ValueView`, lazy + memoized validation, and the resumable `Decoder`).
- `src/value/` is the in-memory reading: a `B`-prefixed class tree (`BValue`→`BAtom`/`BFrame`→ the nine leaves) whose `compare`/`equals` reproduce CE order structurally — nothing here encodes. `visitor.js` is the `Visitor` base plus the iterative `walk`/`fold` drivers; `build.js` the one construction surface plus the `fromForeign` hook; `ce.js` the encoder as a `fold`; `view.js` the bytes→`BValue` bridge and the one-shot `decode`/`decodeAll`.
- `src/btree.js` is `BTree` / `BTreeSet` — the sorted collection behind dicts and sets, presenting the `Map` / `Set` interface.
- `src/text/` reads and pretty-prints the textual syntax through the same builders; `src/ops.js` is a port of blnim's value operations (walk, `similar`, `prefixes`, shapes); `src/lang/rewrite.js` is a rewrite engine. `src/data.js` is the curated public surface.
- `src/json.js` is the JSON dialect (`@bassline/core/json`), a port of `lib/json.nim`: `toJSON` / `fromJSON` over kind-tagged objects (`{kind, mark?, value}`), `toValue` for an already-parsed tree, and `numberReviver` so `JSON.parse` recovers integers of any width from the source. Never canonical, refuse-not-coerce; stricter than the Nim door in that an unknown object key is refused. Needs Node ≥ 22.
- `src/stream/` is the Node transport for CE bytes — a `Transform` over core's `Decoder`, plus a small TCP adapter. It pulls in `node:stream`/`node:net`, so it is the opt-in `@bassline/core/stream` entry, kept out of the portable `@bassline/core/data` surface.
- `test/corpus.test.js` runs the shared corpus (all seven case heads) against this implementation and checks that `corpus.blb` and `corpus.json` still read back as the cases.

`legacy/js` has no README. It stays in the pnpm workspace because `tools/vscode` depends on it.

## State as of 2026-11-20

- The repository is organized into `core`, `dialects`, `tools` and `legacy`, on the branch `reorg`. `tinybl` is now the package `bassline` at `core/nim`.
- Tracks: `add` is the only way to make a slot, `revise` is the holder's own step (it can put any node in a slot, unasked of `keeps`) and raises during another write, slots are never renumbered, and monitors hear `joined`, `added`, `revised` and `left`. Earlier `update`, `delete` and `reset` are gone.
- Ruled 2026-11-20: normalizing a set or dict into repeats raises, with the edit left in place, whether by reifying live members or editing members in place. Silently merging them would hide a change, and the right semantics are open. `Dict` and `Set` drop a repeat they are given, and the text reader refuses one.
- Ruled 2026-10-02: reading text as one value, text that has begun a second value is refused however it ends (`1 [`, `go !`), and empty text is refused; only text running out inside its one value is incomplete. Every reader follows the corpus on this.
- `core/ts`, `core/py` and `core/swift` predate tracks. The jam and the `bl` tools run on `legacy/blnim`, and a jam on `core/nim` tracks, keeping the wire protocol, is open.
- `tools/cli` builds on this branch, and its tests aren't ready to run yet.

## Working here

- `data-model.org` and the codec are load-bearing. Do not change either without an explicit instruction; describe the change and its consequences instead.
- Every door that handles values handles marked values.
- There are no booleans and no non-integer numbers. Those are vocabulary: `(dec 15 -1)`, symbols, presence in a set.
- A reading that cannot hold a value refuses it. Never coerce, truncate, or normalise.
- `cmp` on values is CE order: kind, then mark, then shortlex for scalars, then members with a shorter frame sorting after a longer one that it prefixes.
- Prefer the stdlib to hand-rolled code (`parseBiggestInt`, `lowerBound`). Constants come from C headers, not literals.
- In Nim, `import bassline`, not its modules one by one.
- Build values with `bl"…"`: `bl"(heard $n $v)"` splices the nodes `n` and `v`, and `$name!` marks what goes in. It reads better than building by hand and costs the same. `blet"{foo bar}"` binds symbols. Read a value's shape with `matchValue` rather than checking kind, length and head by hand against constants kept for the comparison.
- Comment only what the code can't say for itself: a compiler workaround, an invariant that isn't visible, a rule borrowed from elsewhere. No doc comments otherwise.
- Name things with ordinary programming words (`pending`, `apply`, `kept`), not coined ones.
- Nothing checked in names a path on one machine. A test or a benchmark makes its own input or takes it on its command line.
- A new kind of track, a monitor, a kind of live object or a reading goes in the dialect it serves, `dialects/NAME`. `core/` holds only what every program needs.
- Benchmark release builds only (`-d:release` is not in `nim.cfg`; pass it).
- Keep each reader’s interpretation local. Across an edge, exchange self-contained values. Preserve the grounds a later reader needs, such as which jam assigned a rank.
- Lifecycle does not propagate. Closing is a local decision.
- A foreign format (JSON, and whatever follows) is read into values losslessly where the host grammar allows and refused where it does not. Going out is lossy; bassline is the richer side. A foreign form is never canonical: the only identity a value has is its CE bytes. On the way in, the door is `toValue`.
- Design documents carry ideas only, in the voice of `data-model.org`. Prior art, comparisons, and sources stay in conversation.

In `core/nim` and `legacy/blnim`, `nim.cfg` is checked in: atlas writes the dependency paths into its section (`atlas install`, into `deps/`, which is gitignored), and the lines outside it are the compiler flags. `atlas link` to a checkout of a dependency writes that checkout's path into the section, so don't commit it. `legacy/blnim/vendor/monocypher` is checked in.

`install.sh` builds the bl toolkit and sets up the jam on a fresh checkout: it checks for Nim and atlas, fetches blnim's dependencies, builds `tools/cli`, links the jam plugin into `~/.claude/skills/jam` and makes `~/.bl/key.blb`.

A `bl-jam` already running, a jam or an agent's line, keeps the build it began with when `nim build` replaces `tools/cli/bin/bl-jam`, until it is started again.
